01 Agent / 自动化
Agent 自动化强烈推荐
moli —— 给 AI Agent 用的无头浏览器，把「渲染」变成按需开关
lexmount/moli 14,727 ★ Rust Apache-2.0 最后提交 2026-10-09
发生了什么：一个用 Rust 写的、面向 Agent 的无头浏览器。核心设计是按需布局与渲染——不渲染时几乎没有资源开销，需要时再开布局。接入面同时提供 CLI、CDP、WebDriver Classic 和 WebDriver BiDi 四种；`moli fetch --dump markdown` 直接输出 Markdown，`--dump semantic_tree_text` 输出模型友好的语义树，加 `--layout` 后可输出视口截图、整页截图或分页 PDF。仓库里自带一个 skills 目录，官方推荐的安装方式是把目录地址交给你的 Agent，让它自己读完说明再装。

为什么值得关注：抓网页对 Agent 一直是个「重决策、重资源」的环节——完整浏览器渲染慢、吃内存，而抓到的又是一大坨 HTML。moli 把「要不要布局、要不要取图/字/音视频资源」拆成开关，并且把 Markdown 和语义树做成一等输出：交给模型的不是像素，而是结构。更值得记的是它的分发姿态——发布 skills、把安装写成一句给 Agent 的提示词，这是「软件为『被 Agent 安装』而设计」的样本，恰好也是 Hermes 这类 Agent 抓取栈最缺的一层。
适合谁：需要稳定抓取、批量内容监控或网页自动化的流程；把 Hermes 当抓取与摘要基础设施用的场景。
快速开始：官方一行安装脚本（macOS/Linux：`curl … moli-installer.sh | sh`），然后把仓库 skills 目录交给 Agent 自行安装；验证用 `moli fetch --dump markdown https://example.com`。
风险与限制：2026-08 才建仓，Trendshift 显示主要贡献者仅 1 人；无头浏览器天然是高攻击面组件，跑不明来源页面需隔离；README 在 Apache-2.0 之外提到另有限制条款，商用前须自行确认。本机未实测。
macOS / 潜力值得关注
Cetus —— 把命令行 Agent 变成 macOS 上常驻的桌面助手
drewnekota/cetus 146 ★ TypeScript MIT 最后提交 2026-10-09
发生了什么：一个 macOS 常驻 App，把 Codex / Claude Code / DeepSeek Harness / 自带 pi runtime 包在桌面层里。四个能力：Quick Launcher（按住两个 ⌘ 键在任何 App 上唤起，自动带上当前截图、前台 App、浏览器 URL、选中文字作为可移除的上下文片）、Automations（把任意提示词变成 at / every / cron / daily 的定时任务，每次跑在独立的背景会话里，结果留给你审）、Global Quick Reply（双击右 ⌥ 读屏起草回复，⏎ 落回原输入框、⇥ 换一个 runtime 重写）、Screen Context（用 Apple Vision 在本机 OCR 定期抓帧并去重，opt-in、可设保留期、可排除 App）。要求 Apple Silicon + macOS 13 以上，复用已有 CLI 登录，不需要二次授权。

为什么值得关注：它没有再造一个 Agent，而是补上命令行 Agent 最缺的三件事——随时可唤起的入口、屏幕上下文、以及「跑完留给我审」的异步执行。屏幕采集全在本机、默认不采集、可排除指定 App，这个取舍对在意素材与客户隐私的创作者是明确的加分项。对已经在用命令行 Agent 的 Mac 用户，这是很薄的一层胶水，却实实在在地把使用频率拉起来了。
适合谁：本机已经在跑 Codex / Claude Code / Hermes 的人；想把「随手问一下」变成肌肉记忆的创作者与开发者。
快速开始：下载 Release 里的 DMG → 拖进 Applications → 选择已登录的 `claude` / `codex` / `dsh` CLI 或自带 runtime。
风险与限制：仅 146 ★、12 fork，个人项目，长期维护不确定；会让 Agent 常驻后台并读取屏幕，授权范围要自己想清楚；在 M4 上的性能与耗电未实测。
02 编码代理 / Codex / Hermes
代码评审强烈推荐
Alibaba open-code-review —— 确定性管线管范围，模型只管判断
alibaba/open-code-review 44,951 ★ Go Apache-2.0 最后提交 2026-10-08
发生了什么：阿里内部跑了两年、2026 年 5 月开源的代码评审 CLI（命令为 `ocr`）。架构是混合式：确定性的工程管线负责上下文裁剪与规则匹配，LLM Agent 负责判断并写出钉到具体行的评论；内置多语言规则集覆盖空指针、线程安全、XSS、SQL 注入等。npm 一行安装，可接任意 OpenAI / Anthropic 兼容端点。项目方称其内部服务了数万名开发者、执行过百万级评审任务，并称相较纯 LLM 方案综合 F1 更高、token 消耗约为 1/9（属项目方与第三方博客口径，未见独立复现）。

为什么值得关注：纯 LLM 评审的两个老毛病是误报多、token 烧得快。这个项目把「该看哪些文件、哪些行」交给确定性管线，把「这一段有没有问题」交给模型——它承认了模型不该做检索和规则匹配，这是本周最值得直接借鉴的工程判断。对任何已经有 CI 的仓库，它基本是「接进去就能用」的一层，而且不绑定模型厂商。
适合谁：有代码仓库、想在 CI 里加一道自动评审的开发者；Hermes 工作流里需要代码审查环节的场景。
快速开始：`npm` 安装得到 `ocr` 命令 → 配置一个 LLM 端点 → 在 git diff 上运行，输出行级评论。
风险与限制：内置规则集偏 Java/Go（阿里主战场），其他语言效果需自测；「1/9 token」是项目方自评口径；默认会把代码发送到第三方模型，私有仓库必须先确认合规。
编码代理值得关注
Kimi Code CLI —— 单二进制、视频输入、对话式配 MCP
MoonshotAI/kimi-code 7,812 ★ TypeScript MIT 最后提交 2026-10-09
发生了什么：Moonshot 官方的终端编码 Agent。几个具体取舍值得注意：单二进制分发，一条安装脚本，不需要 Node.js；TUI 毫秒级启动；支持把录屏或视频直接丢进对话当输入（官方举例：一段参考视频转成 LUT、长视频剪成短片、录屏转成可运行代码）；`/mcp-config` 用对话方式增删与授权 MCP server，不用手改 JSON；内置 `coder` / `explore` / `plan` 子 Agent 在隔离上下文里并行；插件市场可安装 skills、MCP server 与数据源，并且安装时明示每个包的信任级别；还提供生命周期钩子，用来给高风险工具调用设闸审计。可走 Kimi OAuth 或 Moonshot API key，也能配置其他兼容 provider。

为什么值得关注：它把本周几个分散的趋势一次性做进一个 CLI：分发摩擦降到最低（单二进制）、多模态输入进入编码 Agent 的日常（视频）、MCP 配置去 JSON 化、以及把「信任级别」暴露在安装环节——当 skills 生态开始有供应链问题，这个先手很有价值。对已经用 Codex / Claude Code 的人，它值得当作第二个后端来做价格与能力的横向对比。
适合谁：想给编码 Agent 换一个非美系后端做对比的人；需要把视频/录屏作为输入的场景。
快速开始：`curl -fsSL https://code.kimi.com/kimi-code/install.sh | bash` → 新开终端 `kimi --version` → 进目录 `kimi`，首启 `/login` 选择 OAuth 或 API key。
风险与限制：背靠 Moonshot，默认体验强绑定自家模型（换 provider 的体验未核实）；账号体系与国内网络访问需自行处理；本机未实测。

ArtCraft —— 「艺术家的 IDE」：先把构图摆定，再让模型生成
storytold/artcraft 10,441 ★ Rust 许可证标记 Other / NOASSERTION 最后提交 2026-10-07
发生了什么：自称为「艺术家的 IDE」，做交互式 AI 图像与视频创作：在 2D 里合成、在 3D 里搭景，再选择适合的模型生成。README 列出的能力包括图生场景（把虚拟演员放进一致的房间环境、同场景规划多个镜头）、2D/3D 图像合成、图像转 3D 网格、角色摆姿、用 kitbashing 做场景调度以控制机位与景深、角色身份迁移（用摆好姿势的人台引导角色位置与姿态）、背景分离、混合素材合成。Rust 编写的独立应用，Trendshift 记录它在 2026-10-06 首次进入全语言 Trending 榜。

为什么值得关注：它回答的正是修图师最痛的问题——生成图不可控。ArtCraft 的路线不是「更好的提示词」，而是把构图、机位、角色身份这些在生成之前就用手摆定，再让模型成为一个可复现的渲染环节。这跟你在 Hey，Alpaca！ 里坚持的「先把版面、坑位、文字位置定下来，再填内容」是同一条逻辑，只是它发生在图像生成层。同一作者还在用 Rust 重写一串创意软件（见下一条），这股潮流本身就是本周最清楚的信号之一。
适合谁：需要可控构图、角色一致性与「同场景多镜头」的设计师、摄影师、修图师；想找 PS 之外第二块画布的人。
快速开始：官网 getartcraft.com 或 GitHub Releases 直接下载，也可从源码构建。
风险与限制：许可证标记为 Other / NOASSERTION，商用前必须自行核查；重度依赖模型与 GPU，M4 上的实际性能与模型接入方式未核实；是一个体量不小的应用，学习成本不低。
视频值得关注
FilmCraft —— 建仓 9 天的「纯 Rust 版 Premiere」，且每个操作都是一条可被 Agent 驱动的命令
storytold/filmcraft 6,503 ★ Rust Apache-2.0 建仓 2026-09-30 · 最后提交 2026-10-09
发生了什么：与 ArtCraft 同门的「清洁室重写版」非编软件：纯 Rust，原生 macOS / Windows / Linux，也可通过 WebAssembly 跑在浏览器里。技术上几个点很硬——H.264、HEVC、ProRes、AAC 的编解码器是团队按公开规范自己写的；GPU 合成器在线性光下工作；帧运算走精确整数时间，因此剪辑不会随时间漂移；界面刻意对齐 Premiere 的面板、工作区与快捷键，三点编辑、各种修剪、动态修剪、Trim Monitor 都在。README 里最关键的一句是：App 里的每一个动作都是一条命令，AI Agent 可以像你一样精确驱动它。

为什么值得关注：建仓 9 天就 6.5k 星，说明「Rust 重写专业创意软件」在 2026 年有真实需求，而不是极客自嗨。更值得记住的是它的架构选择——把 UI 操作全部命令化，于是 Agent 自动化不是外挂的模拟点击，而是原生能力。这对「让 AI 参与修图/剪辑流程」是个方向性提示：与其让 Agent 去点鼠标，不如让软件本身就可以被命令驱动。
适合谁：视频剪辑与调色从业者；关注「创意软件如何原生支持 Agent」的产品与工程人员。
快速开始：GitHub Releases 下载桌面版，或直接用浏览器版；官网在 getartcraft.com。
风险与限制：9 天的新项目，功能完整度与稳定性都不可能等价于 Premiere，切勿直接进生产流程；编解码器自研意味着格式兼容性需逐一实测；WebAssembly 版本性能未知。

storytold/artcraft · 10,441 ★ · Rust · 最后提交 2026-10-07 · 许可证标记 Other

它真正卖的是什么。不是模型，也不是提示词技巧，而是「在生成之前把不确定性消掉」的工作方式：用 2D 图层做合成、用 3D 场景定机位与景深、用摆姿人台锁定角色身份，然后才出图。修图师对这套逻辑是熟悉的——这就是图层与蒙版的思路，只是它把图层从二维抬到了三维，并且把「生成」降级成链条中的最后一步。

对你为什么相关。你在 Hey，Alpaca！ 里已经证明过这条路径的价值：先把版面、坑位框、文字位置定好，再往里填内容，结果才可控、可复现。ArtCraft 把同一个原则用在了图像生成上。所以它对你的价值不一定是「换一个工具」，而是一个可以对照的参考实现——如果你的产品未来要处理「可控地生成背景/道具/素材」，它示范了交互该怎么设计、控制点该落在哪。

该不该动手试。值得试，但要限定范围：先用它做一个具体的、你本来要手工合成的镜头（例如同一房间的第二个机位，或角色姿态一致的延展图），只关注一件事——把构图摆定之后，出图的命中率是否真的比纯提示词高。这是唯一能把「看起来很对」变成「确实有用」的验证方式。

该不该进技术储备。方法论层面：该，而且优先级高于工具本身。工具层面：先观望——许可证标记为 Other、需要自行核查商用条件，重量级依赖模型与 GPU，M4 上的实际表现没有可查的公开数据。把它当一个持续跟踪的参考，而不是明天就要替换掉的工具。

第一条线：从「比模型」到「比脚手架」。本周榜单里星标最高的两个项目——一个技能集合和一个 harness 清单——都不包含任何模型。它们卖的是「模型该被怎么用」：上下文怎么投递、工具怎么设计、权限怎么设闸、验证怎么落进 CI。当各家模型价格收敛、能力差距被抹平之后，可复现性的来源就从权重转移到了脚手架。这是本周最清楚的一条趋势，也是最容易被忽略的一条。

第二条线：分发在变轻，扩展在变重。Kimi Code 用单二进制 + 免安装 Node 的脚本换掉了一大半环境摩擦；mattpocock/skills 把技能挂进各家的插件市场做自更新；moli 干脆把安装写成一句给 Agent 的提示词。与此同时，扩展侧的治理在变重——Kimi Code 在安装时明示信任级别，awesome-harness-engineering 专门辟出「权限与授权」「安全与沙箱」两节。装得更容易，管得就要更严，这两件事必须同时发生。

第三条线：创意软件被重写，而且原生面向 Agent。ArtCraft、FilmCraft 同一个团队、同一周、同一个技术选择：Rust、清洁室、精确整数时间、可被命令驱动。FilmCraft 建仓 9 天就 6.5k 星，说明需求是真实的。对做创意工具的人来说，这里有一个很具体的判断——「让 AI 帮你操作软件」和「让软件本身可被命令驱动」是两条完全不同的路，后者更难，但更持久。

下周看点：这批项目里最需要在 Real 场景下被质疑的，是「按需渲染的 Agent 浏览器」和「桌面常驻 Agent」这两类——它们都要求把权限交出去一部分。另一件值得盯的事：当 skills 成为主要分发单元之后，谁会先做出一套真正的技能版本管理（可回滚、可审计、可锁定），这可能比再多出十个技能库更重要。
